# 3. Данные, доверие и provenance

## Три разных вопроса

Для любого значения Portal Air стремится хранить ответы:

1. **Что источник прислал?**
2. **Что система из этого распознала?**
3. **Что мы имеем право утверждать о физическом смысле значения?**

Эти вопросы нельзя объединять.

## Временные метки

Минимально различаются:

- `observation_time` - время измерения/наблюдения;
- `receipt_time` или `fetch_time` - когда данные получил наш сервер;
- publication/report/model run time - если внешний provider публикует отдельную временную семантику.

При replay или задержке observation time не должен заменяться временем получения.

## Отсутствие данных

Нет данных ≠ ноль.

Gap может означать:

- устройство не отправило пакет;
- Wi-Fi был недоступен;
- Internet был недоступен;
- сервер был недоступен;
- upstream provider не ответил;
- пакет не прошёл parsing;
- данные ещё не были опубликованы.

Без дополнительного evidence система не должна автоматически выбирать одну из этих причин.

## Duplicate и delayed delivery

Повторная доставка полезна как transport evidence, но не должна создавать неразличимый второй физический observation.

Для этого нужна deterministic identity события/измерения и отдельный учёт attempts/delivery.

## Классы внешних источников

| Класс | Смысл |
|---|---|
| `OBSERVATION` | Фактическое физическое наблюдение. |
| `AGGREGATED_OBSERVATION` | Наблюдения, представленные агрегатором/архивом. |
| `CROWDSOURCED_OBSERVATION` | Измерение общественной/частной станции. |
| `MODEL` | Значение расчётной модели. |
| `FORECAST` | Прогноз на будущий valid time. |
| `REANALYSIS` | Ретроспективный расчёт с переобработкой данных. |
| `MIXED` | Источник смешивает provenance или model substitution. |
| `SAME_UPSTREAM_REDUNDANCY` | Другой API доставляет фактически тот же upstream. |

## Почему нельзя просто усреднить всё

Например:

- аэропортовая станция;
- домашний анемометр между зданиями;
- grid model;
- forecast;
- собственный датчик Portal Air

могут все показывать "скорость ветра", но измеряют/описывают разные пространственные и временные условия.

Поэтому source class, coordinates, timestamps и upstream provenance являются частью данных, а не дополнительным описанием.
